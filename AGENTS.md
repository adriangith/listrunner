# ListRunner agent notes

- There is no root `package.json` or shared workspace runner. Run npm commands from the package being changed; each package has its own lockfile.
- The iOS app and its Capacitor plugins were removed in preparation for a native SwiftUI rewrite. `plan.md` is the current product/architecture spec; consult the OpenPencil design in the project before implementing UI. Old dated docs/specs may describe the removed Capacitor implementation.
- Focused core checks: `cd packages/core && npm test && npm run typecheck` (Vitest). `packages/extension` and `packages/harness` remain separate browser targets: extension checks use `npm run build` and `npm run typecheck`; harness uses `npm run dev` or `npm run build`.
- `packages/prototype` is a standalone, simulated iPhone-flow prototype (not the mobile app and does not contact Coles): `npm start` serves on port 4178; `npm run check` syntax-checks its JS.
- `plan.md` and design specs may describe desired behavior, not necessarily the implementation. Verify current code and tests before treating a requirement there as implemented.

## Linux / Mac development and handoffs

- Exchange changes through the same Git remote, not ad-hoc `scp`, folder mirroring, or iCloud. Linux is the usual editing location; the Mac builds, signs and tests committed revisions. Mac-side fixes must be committed and pushed back before Linux resumes the task.

- Before editing or switching branches, inspect Git status, branch, remote and current commit on the machine involved. Preserve unfamiliar/uncommitted work; never reset, clean, force-push, force-checkout, or overwrite it to make copies match.
- One session owns a task's writable checkout at a time. Independent concurrent tasks use separate branches and worktrees; do not edit the same files from multiple sessions. Follow the user's worktree preferences and ask before moving a session unless separate work was already requested.
- Handoff: commit and push the task branch; record its branch and full commit SHA plus validation results. The receiving machine must have a clean or explicitly preserved working tree, fetch, and check out that exact revision before building. Do not pull blindly into divergent or dirty branches. A local commit is not backed up to the remote until pushed.
- Keep one canonical tracked Xcode project, shared scheme, source, assets, tests and store resources. Reconcile the working Mac configuration without losing signing/resource references; do not maintain permanent Linux/Mac project variants or duplicate `-v2` resources. Keep genuinely machine-specific overrides and secrets outside tracked shared configuration.
- Generated output belongs outside the checkout, especially outside cloud sync. Exclude DerivedData (including `work/DerivedData`), dependencies, temporary test results, `.DS_Store` and Xcode `xcuserdata` from Git as appropriate. Ignore rules do not prevent cloud uploads: the Mac checkout itself must be outside iCloud. Do not delete simulator state, test evidence or credentials as generic cache cleanup.
- Git is not a backup for uncommitted/ignored work. Before migration, snapshot both copies, preserve Mac-only files and local commits, and verify the backups. Keep a separate ongoing backup. Finish migration by comparing canonical files and running relevant tests plus a Mac build; report the verified revision and remaining differences honestly.
